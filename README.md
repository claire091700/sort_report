# sort_report
排序演算法分析報告：效能評估與理論實證一、 前言排序（Sorting）是資訊科學中最基礎且重要的運算之一。無論是搜尋引擎的資料檢索，還是嵌入式系統的訊號處理，高效的排序演算法皆能顯著提升系統效能。本報告旨在透過實作五種經典排序法，觀察其在不同數據規模下的表現，並驗證理論複雜度與實際執行時間的關聯。二、 排序演算法原理說明1. 氣泡排序法 (Bubble Sort)原理：重複走訪要排序的數列，一次比較兩個元素，如果他們的順序錯誤就把他們交換過來。操作：每一輪都會將剩餘數列中最大的元素「浮」到最右端。2. 選擇排序法 (Selection Sort)原理：在未排序序列中找到最小（大）元素，存放到排序序列的起始位置。操作：不斷從剩餘元素中尋找極值，並與未排序部分的第 1 個元素交換。3. 插入排序法 (Insertion Sort)原理：將資料分為「已排序」與「未排序」兩部分，逐一將未排序元素插入已排序序列的適當位置。操作：類似玩撲克牌時整理手牌的方式。4. 合併排序法 (Merge Sort)原理：採用分治法 (Divide and Conquer)。將大問題分成小問題解決，再將結果合併。操作：遞迴地將數列對半切分直到剩單一元素，再依序合併成有序數列。5. 堆積排序法 (Heap Sort)原理：利用「堆積」這種資料結構所設計的排序演算法。操作：先將數列建成最大堆積（Max Heap），不斷將根節點（最大值）與末尾節點交換，並重新調整堆積。三、 複雜度分析比較排序法最佳時間複雜度平均時間複雜度最差時間複雜度空間複雜度穩定性氣泡排序$O(n)$$O(n^2)$$O(n^2)$$O(1)$穩定選擇排序$O(n^2)$$O(n^2)$$O(n^2)$$O(1)$不穩定插入排序$O(n)$$O(n^2)$$O(n^2)$$O(1)$穩定合併排序$O(n \log n)$$O(n \log n)$$O(n \log n)$$O(n)$穩定堆積排序$O(n \log n)$$O(n \log n)$$O(n \log n)$$O(1)$不穩定四、 實驗設計與資料模擬1. 實驗環境程式語言：C++ / Python (請根據你的實作填寫)測試環境：CPU / RAM 規格計時方式：使用 <chrono> 或 time 函式庫記錄執行毫秒數 (ms)。2. 數據規模設定實驗採用隨機生成的整數數列，設定以下三種規模（$n$）：小規模：$n = 1,000$中規模：$n = 10,000$大規模：$n = 100,000$五、 實驗結果呈現與比較1. 執行時間比較表 (單位：ms)資料量 (n)氣泡排序選擇排序插入排序合併排序堆積排序1,000(填入數據)(填入數據)(填入數據)(填入數據)(填入數據)10,000(填入數據)(填入數據)(填入數據)(填入數據)(填入數據)100,000(填入數據)(填入數據)(填入數據)(填入數據)(填入數據)2. 效能分析觀察$O(n^2)$ 演算法（氣泡、選擇、插入）：當 $n$ 增加 10 倍時，執行時間約增加 100 倍，符合二次方增長的理論。$O(n \log n)$ 演算法（合併、堆積）：在大數據規模下，表現遠優於前三者，時間增長接近線性。六、 心得與結論1. 個人觀察在實作過程中發現，插入排序在處理「幾近完成排序」的資料時效率極高。而氣泡排序雖然邏輯最簡單，但在大數據量時簡直是災難。合併排序雖然速度快，但需要額外的記憶體空間（空間複雜度 $O(n)$），這在記憶體受限的硬體環境中需要權衡。2. 總結小型資料集 ($n < 1000$)：五種演算法差異不大，甚至插入排序可能因為常數項較小而更快。大型資料集 ($n > 10000$)：必須選擇合併排序或堆積排序，否則時間成本過高。穩定性需求：若資料具備多種權重（如：先依分數排，再依學號排），應優先考慮合併排序或氣泡/插入排序，而非不穩定的堆積或選擇排序。
